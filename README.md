# 捷程未来PLM

Python 3.10+ 标准库服务，SQLite 数据库，本地图片和附件存储。不使用 Docker。部署包包含已构建的前端，运行时无需 Node.js 或 pip。

## 启动

从 GitHub 克隆源码后，先运行 `npm ci && npm run build`。使用部署包可直接启动。

```sh
./start.sh
```

打开 http://127.0.0.1:8787，首次填写管理员用户名、邮箱和密码。

局域网：

```sh
./start.sh --host 0.0.0.0 --port 8787
```

## 使用

- 登录后先选择项目。产品、BOM、物料、供应商、采购和库存仅显示当前项目的数据。管理员可在「项目设置」顶部归档或恢复项目，也可输入当前管理员密码删除已归档项目。删除后在项目工作台的「已删除」可撤销。项目成员在项目设置中分配。
- 项目首页按封面卡片展示。在「项目设置」可上传或粘贴封面，未设置时优先显示该项目已有的产品图片。
- 产品经理可从当前项目成员和系统管理员中选择。
- 旧版数据库首次升级时归入「存量项目」，原料号、二维码和历史记录保留。项目归档后可查询和导出。账号、登录记录和整站备份在系统设置管理。
- 新建产品、物料或供应商时只要求名称。物料的类别、规格、单位、价格、库位、备注和图片可在新建时选填，单位默认 PCS。其他信息直接展开。新建表单和「编辑产品」顶部可粘贴图片，也可按 ⌘V / Ctrl+V。
- BOM、物料库和库存查询分别显示「一级物料」和「二级物料」。类别是可搜索的单选，输入新名称后可新增到当前项目。
- 料号单独固定在首列。拖动表头把手调整其他字段顺序，拖动表头右边缘调整列宽，双击右边缘恢复默认。点「显示字段」勾选需要的列。当前浏览器会记住列的显隐、顺序和宽度。可从「类别」表头按项目类别筛选。
- 点击操作列的铅笔可编辑物料资料。名称、图片、料号、库存和成本小计在表格内只读，图片可在物料详情维护。
- 物料、供应商和产品等资料下拉可直接新建，保存后自动选中，保留当前表单内容。
- 规格、单位、用量、价格、位号、备注等支持表格内编辑。回车或离开输入框保存，Esc 取消。库存只由入库、出库、退库和报废计算。
- 一级物料详情有「二级物料」入口，可新增二级物料或多选关联已有物料，每条关联记录有独立用量。从该入口新建时自动关联当前一级物料。
- 二级物料的「关联一级物料」字段支持多个一级记录，显示为可点击的标签，支持搜索、多选、查看和筛选。两侧修改同一组关联，不重复创建物料。
- 取消关联不会删除物料或改变库存。有关联时不可直接调换一级/二级，需先解除关联。关联是物料之间的双向关系，不关联其他产品的子 BOM，也不自动扣减库存、计算组装成本或向产品 BOM 插行。
- 二级物料列表和 BOM 可切换显示「关联一级物料」列，物料列表还可按一级物料筛选。
- 在产品 BOM 内新建物料，默认用量 1；也可以从当前级别中添加已有物料。
- 在物料编辑的「关联 BOM」中可添加或移除产品的指定 BOM 版本。新增用量默认 1，原有用量保留。在产品 BOM 移除物料后，该版本的关联也会从物料详情移除。
- BOM 新版本复制当前版本的明细，版本号自动递增；旧版本仍可编辑。共享物料的当前价格和库存用于所有版本，历史成本不是价格快照。
- 一级 BOM 的 CSV 导入会复用已有料号。找不到料号时，按物料名称建档、自动生成料号，并把原编号留作外部料号。导出包含当前级别及所选类别。
- 在二级 BOM、一级物料详情的二级物料页或二级物料库可导入电子物料 XLSX / CSV。确认预览后新建或复用二级物料。表内编号存为外部料号，系统编号自动生成。不贴、不焊和测试点默认不勾选，可手动纳入。
- 物料和供应商可多对多关联，双方详情都可以添加、查看和解除关联。采购单价和采购链接选填。
- 物料行的回形针可打开图片与附件，上传图片、规格书或图纸。显示及下载名称使用「料号 物料名称（序号）」并保留扩展名，产品文件使用产品编号和名称。
- 采购单支持多物料、分批入库和自动入库状态。出库可关联产品，退库必须关联原出库，报废须填写原因。
- 物料二维码可下载、打印。扫码后进入物料详情；摄像头扫码需要 HTTPS 或 localhost，扫码枪也可直接输入物料编码。

## 生产检测

- 进入项目后打开「生产检测 → 检测录入」。手输或扫码填写 S/N 后点「登记设备」。设备会立即出现在「设备台账」，还没设置检测表也能登记。保存检测或导入记录也会登记对应设备。
- 支持扫码枪、摄像头连续识码、摄像头拍照和上传条码照片。用完整 S/N 读取对应设备记录，按前 6 位载入最近一条检测或查看全部。保存后自动清空并聚焦 S/N，继续扫下一台。
- 管理员在「检测表设置」配置编号、分组、检测项类型、必检项和判定条件。多选可允许现场新增，保存后可在同一检测表复用，管理员可隐藏或恢复这些选项。
- 「检测记录」支持关键词、前缀范围、日期和结果筛选，查看各检测项、排序、分页，导出当前页或全部筛选结果。管理员可预览 Excel／CSV 导入，跳过重复 S/N，也可删除和恢复检测记录。
- 点击检测记录里的 S/N，弹窗顶部会显示关联订单号。点击非 KS 订单号可在全局发货中定位对应行。补发记录显示主订单号，点击后定位到关联设备的子订单。KS 订单可点开查看发货详情。
- 每个项目独立保存设备台账、检测表和记录。旧记录保留当时的表单版本，检测数据随整站备份一起保存。

## 发货管理

- 左侧「全局发货」汇总各项目的「其他发货管理」。在任一入口登记或修改，另一边读取同一份记录。KS 发货在项目内管理，收件资料、SKU 和商品数量从关联的「KS 发货信息」读取。
- 全局发货登记时先勾选经办项目，商品下拉列表只显示这些项目的产品。一个订单可包含多个项目的商品，项目台账各自只显示本项目的商品。项目新增产品后，「其他发货管理」会自动出现对应的数量列。
- 发货状态、来源、承运商、国家地区和经办项目使用色签。点击发货商品或打开记录详情可看产品缩略图，商品选择列表也显示首图。
- 全局台账按订单号显示，滚动时自动加载更多。发货商品在同一格显示，未填商品也能保存，未匹配的商品标为「待关联」。普通订单显示一行，补发时用「＋」新增可折叠的子订单。项目内的 KS 和其他发货台账也支持子记录，编辑时可关联或解除父记录。
- 点击订单号查看详情，可在全局和项目台账之间定位并高亮对应行。删除的记录可在所属项目台账的「已删除」中恢复。

## 产品代号与物料编号

产品可填写英文代号，例如 `AQUAMIX`。英文代号自动转大写，至少含两个英文字母，可使用数字、连字符、下划线，最多 32 位；完整代号不能重复，前两位相同的不同代号可以并存。

物料编号规则：**固定前缀 JC + 类别 1 位 + 级别 1 位 + 全系统 4 位流水号**。

| 部分 | 规则 | 示例 |
| --- | --- | --- |
| 前缀 | 全系统统一为 JC | JC |
| 类别 | 1 结构、2 电子、3 自定义 | 2 |
| 级别 | 1 一级、2 二级 | 1 |
| 流水号 | 全系统统一递增 0001–9999 | 0001 |

示例：`JC210001`、`JC220002`、`JC110003`。不同物料的末四位全系统唯一，删除后不回收。达到 9999 时阻止新增。

物料库、BOM 和批量导入使用同一编号规则。升级时现有料号统一改为 JC 前缀，类别、级别和流水号保留。旧料号仍可用于扫码查询和 CSV 导入，已生成的二维码链接继续有效。修改类别或级别时保留原流水号。

关联交互参考 [飞书多维表格双向关联字段](https://www.feishu.cn/hc/zh-CN/articles/653027931590-%E4%BD%BF%E7%94%A8%E5%A4%9A%E7%BB%B4%E8%A1%A8%E6%A0%BC%E5%8F%8C%E5%90%91%E5%85%B3%E8%81%94%E5%AD%97%E6%AE%B5)。本系统独立运行，不连接飞书账户。

## 构建与测试

修改源码后需要 Node.js 18+（推荐 20+）：

```sh
npm ci
npm run build
python3 -m unittest discover -s tests -v
python3 scripts/package-release.py
```

部署包生成在上级 `releases/jiecheng-plm-1.9.8.tar.gz`，不包含数据库、密码、图片、node_modules 或测试数据。

## 部署到服务器

将部署包上传并解压到空目录：

```sh
tar -xzf jiecheng-plm-1.9.8.tar.gz
cd jiecheng-plm
./start.sh --host 127.0.0.1 --port 8787
```

服务器只需要 Python 3.10+。可以使用宝塔/1Panel 的进程管理器，工作目录设为解压后的程序目录，启动命令为 `python3 server/app.py`。

Linux systemd 示例（程序目录 `/opt/jiecheng-plm`，数据目录 `/var/lib/jiecheng-plm`）：

```sh
sudo useradd --system --home /var/lib/jiecheng-plm --shell /usr/sbin/nologin jiecheng-plm
sudo install -d -o jiecheng-plm -g jiecheng-plm -m 700 /var/lib/jiecheng-plm
sudo cp /opt/jiecheng-plm/deploy/jiecheng-plm.service /etc/systemd/system/jiecheng-plm.service
sudo systemctl daemon-reload
sudo systemctl enable --now jiecheng-plm
```

已有同名用户时跳过 `useradd`。日志：`journalctl -u jiecheng-plm -f`。

将 `deploy/nginx.conf` 的 `location /` 合并到现有 HTTPS 域名配置，代理至 `http://127.0.0.1:8787`。保留 `Host $http_host`，上传限制设为 `20m`。示例 systemd 服务开启安全 Cookie，HTTP 内网使用时将 `PLM_SECURE_COOKIE` 改为 `0`。

开放服务器访问前，可在终端初始化管理员。命令从标准输入读取临时密码，账户首次登录需更改密码。

```sh
python3 server/app.py --bootstrap-admin '管理员姓名' admin@example.com
```

部署到 `/JPLM/` 时使用 `deploy/nginx-jplm.conf`，并设置 `PLM_BASE_PATH=/JPLM`、`PLM_SECURE_COOKIE=1` 和 `PLM_DISABLE_SETUP=1`。

### 配置

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PLM_HOST` | `127.0.0.1` | 监听地址 |
| `PLM_PORT` | `8787` | 监听端口 |
| `PLM_DATA_DIR` | 程序目录下 `data` | 数据库与附件目录 |
| `PLM_SECURE_COOKIE` | `0` | HTTPS 设置为 `1` |
| `PLM_BASE_PATH` | 空 | 部署路径前缀，例如 `/JPLM` |
| `PLM_DISABLE_SETUP` | `0` | 已通过终端初始化时设为 `1`，关闭网页创建管理员 |
| `PLM_QUIET` | `0` | `1` 关闭访问日志 |

`--host`、`--port` 优先于对应环境变量。

## 升级、备份与恢复

升级前在「设置与数据」下载完整 ZIP 备份，然后停止服务。替换程序文件，保持原 `PLM_DATA_DIR` 不变，再启动。升级到 1.3 会新增产品英文代号、编号归属、全局流水号及双向关联表，并自动转换为新物料编号；升级前数据库保存在 `plm.before-v4.sqlite3`。原物料 ID、库存、采购、BOM 明细和附件不变。空白单位补为 PCS，已有明确单位保留。历史物料编号仍可用于扫码枪查询和 CSV 导入。既有物料只归属于一个明确产品 BOM 时自动选用该产品作为编号归属；跨多个产品的物料归为通用编号。

升级到 1.4 会添加外部料号、品牌和二级物料导入记录。有业务数据时会自动保存升级前数据库 `plm.before-v5.sqlite3`。

升级到 1.4.2 后，供应商关联可以不填报价。由上一版升级时自动备份数据库到 `plm.before-v6.sqlite3`。

从 1.0 直接升级时，会同时新增级别字段：旧电子物料默认二级，结构物料及旧组件默认一级。旧的产品子 BOM 关系解除，不自动推断物料之间的新关联。

程序更新后需重启 Python 服务，前端刷新后生效。

若原部署已使用 `/opt/yanwu`、`/var/lib/yanwu` 或旧服务名，可继续沿用，**不要为了重命名另建空数据目录**。在现有服务工作目录替换程序文件即可。

1.5 将原管理员迁移为邮箱账户，原密码可继续使用。迁移前可设置 `PLM_ADMIN_EMAIL` 和 `PLM_ADMIN_NAME`；默认邮箱为 `admin@localhost`。已有业务记录的责任人可在详情补填，历史库存流水保留原样。

管理员可在「设置与数据 → 备份与恢复」下载完整 ZIP，或上传不超过 1 GB 的数据库版本 6 至 8 的备份。恢复覆盖当前数据，旧会话失效。版本 6 备份保留当前账户，版本 7 及以上会还原备份中的账户。覆盖前的 ZIP 保存在数据目录的 `before-restore.zip`。备份含用户资料和密码哈希，需私下保管。

忘记密码时，由服务器管理员停止服务后执行：

```sh
python3 scripts/admin.py reset-password --email admin@example.com --data-dir /var/lib/jiecheng-plm
```

通过隐藏提示输入新密码。已有会话将失效。程序启动时和运行期间每 24 小时检查一次，清理上传目录中超过 7 天且无记录引用的图片。`cleanup-files` 子命令可在停止服务后手动清理无引用的遗留文件。

## 范围与约束

单工作空间，管理员可创建成员并重置密码。成员可修改自己的手机号、头像和密码。产品经理、物料管理员、采购负责人和库存经办人分别记录。采购单当前支持修改负责人。物料删除后可以恢复，原库存、BOM 和采购等关联保留。产品删除须由当前管理员验证密码，关联库存流水的产品可归档。库存流水不能直接修改或删除。

图片支持 PNG、JPG、JPEG、WebP、GIF、BMP，其他附件下载到本地查看。单次最多 12 个文件、总计 20 MB。数量最多 6 位小数，价格用于研发成本估算。手机摄像头及实体扫码枪需在实际设备与 HTTPS 环境验收。
