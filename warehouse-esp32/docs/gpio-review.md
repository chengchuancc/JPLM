# GPIO 分配与 SVG 原理图核对

日期：2026-11-13。依据：`../hardware/SCH_Schematic1_1-P1_2026-11-13.svg`。

## 结论与旧记录更正

当前 GPIO 分配未发现重复占用、业务信号占用启动配置脚或占用 GPIO35～37 的问题。USB 使用 GPIO19/20，BOOT 使用 GPIO0。

之前基于 PNG 的表存在相邻引脚错位，已由本表完整替换：

- KEY_SCAN 经 R8 接 GPIO4，并未接 EN，撤回“按扫码键会复位”的判断及迁移建议。
- KEY_R3 实际 GPIO8，KEY_R4 实际 GPIO9；GPIO3、GPIO46 均未使用，撤回有关键盘占用启动脚和 GPIO46 限制扫描方向的判断。
- ER_EN、ER_TRIG、UART、键盘列与 BUZZER 编号亦已更正。旧表不可作为固件依据。

核对方法：读取 SVG 的模组 `part_pin` / `pin-bar` 路径端点，并与导线坐标、同名网络标签逐项对照，避免用文字基线猜测连接。此结果不是 EDA 网表/ERC，也不等于硬件实测。

### 未使用引脚

图中 GPIO2、GPIO3、GPIO14、GPIO35、GPIO36、GPIO37、GPIO45、GPIO46、GPIO47、GPIO48 及 UART0 的 TXD0/RXD0 未接业务信号。这里只描述图纸，不能把所有未接脚都视为可分配：

- 若最终采用八线 PSRAM 的 N16R8 模组，GPIO35～37 应继续保留，按实际模组手册核对。
- GPIO3、GPIO45、GPIO46 属启动配置相关引脚；GPIO46 仅输入。
- GPIO0 保留 BOOT，GPIO19/20 保留 USB，不能随意复用。

## 仍需核实的电气与固件事项

1. **扫码模块 UART**：按 ER006 手册确认 FPC 的 TX/RX 定义、逻辑电平、波特率和触发协议；串口可通过 GPIO 矩阵分配，GPIO17/18 不必固定对应 UART0。
2. **模块断电反灌**：ER_EN 关闭模块后，UART TX、TRIG 等信号不能持续向模块供电，需结合模块手册安排引脚状态或电路隔离。
3. **屏幕 BLK**：若是逻辑控制输入，可以由 GPIO40 驱动；若直接承担背光 LED 电流，则需按电流设计限流和驱动。屏幕尺寸不能唯一确定驱动芯片。
4. **屏幕片选**：图中为 7 针接口，未见独立 CS。确认实际模块的片选处理方式后再配置 SPI 驱动。
5. **键盘扫描**：行列均为普通双向 GPIO，可选扫描方向。选定一侧为输入并配置可靠上拉/下拉；未选通的输出线宜高阻，避免多键使相反电平输出相连。未见隔离二极管，不能宣称支持任意多键组合。
6. **独立扫码键**：GPIO4 应配置输入上拉或增加外部上拉；R8 是串联电阻，不是上拉电阻。固件需消抖。
7. **电池 ADC**：图中为 100kΩ/100kΩ 分压与 100nF 电容。电池 4.2V 时采样点约 2.1V，应选择覆盖该范围的 ADC 衰减并校准；不要假定满量程是 3.3V。
8. **供电**：GPIO 无冲突不代表供电通过审查，仍需确认扫码补光、背光与 Wi-Fi 的峰值电流、LDO 热设计、电池保护及边充边用方式。
