# JPLM ESP32 扫码枪

实物主控为 ESP32-S3-WROOM-1，使用模组板载 PCB 天线。当前固件按 16 MB Flash、8 MB PSRAM 编译，配瀚彩 ST7789 240×240、5×4 矩阵键盘、独立扫码键和 GPIO21 蜂鸣器。引脚见 [GPIO 核对表](../docs/gpio-review.md)。

## 烧录与首次配网

1. 在 VS Code 打开本目录。默认环境是 `esp32s3`，点击 PlatformIO **→ Upload**，或运行 **扫码枪：烧录仓库应用**。屏幕、矩阵键、扫码模块和蜂鸣器的离线自检仍可用 **扫码枪：烧录首板自检**（`bringup` 环境）。
2. 手机连接屏幕上的 `JPLM-xxxx` 热点，使用屏幕显示的密码。打开屏幕上的 `http://192.168.4.1`，填写办公室 **2.4 GHz Wi-Fi** 名称和密码。
3. Wi-Fi 连上后，扫码枪会保存配置，关闭热点并自动向 JPLM 登记。管理员进入 **系统设置 → 扫码枪**，核对后台和设备屏幕显示的识别码，分配经办人并启用。已配对的设备升级后沿用原登记。
4. 用 **上 / 下** 选择用户，按 **确定** 登录。用户必须事先在网页完成初始密码修改。扫码枪会话只用于仓库接口，项目权限仍由 JPLM 校验。用户选择第一页按 **左** 可重新配网。

PlatformIO 命令为 `pio run -e esp32s3`、`pio run -e esp32s3 -t upload`、`pio device monitor -e esp32s3`。USB 监视器为 115200。首次设备不出现时，按住 **BOOT**，按一下 **RESET**，再松开 **BOOT**。烧录前关闭串口监视器。

## 操作

- **查料**。扫 PLM 物料二维码或物料编号条码。手输时屏幕预填 `JC`，输入其后的 6 个数字，按 **确定** 查找。**左** 删一位；**返回** 清空搜索或返回用户选择。扫码优先切到新物料页。当前用户最近查过的物料可先显示名称，库存和登记权限须等 PLM 确认。
- **库存登记**。物料详情显示编号、名称、库存、单位、PLM 物料管理员和可用的缩略图。按 **入库 / 出库 / 报废** 进入数量页，支持整数 1～999999。**左** 删一位，**返回** 回物料页，**确定** 提交。
- **数量显示**。库存和历史数量略去小数末尾的零。例如 `12.00` 显示为 `12`，`12.50` 显示为 `12.5`。
- **历史与删除**。从仓库首页按 **右** 查看当前用户的记录，列表优先显示物料名称，其次为类型和数量。用 **上 / 下** 选记录，**左 / 右** 翻页，按 **确定** 看详情。详情中连续两次 **确定** 才请求删除并由 PLM 重算库存。**返回** 逐级退回，**刷新** 重读列表。
- **扫码反馈**。GPIO16 开漏拉低触发，超时 3 秒。UART1 默认 9600-8-N-1，接收 CR/LF 分隔或空闲 150 ms 的帧，最大 512 字节。超长帧和非法控制字符会被丢弃。扫码或请求失败时屏幕提示并发出较长的低音。
- **电量和声音**。状态栏显示单节锂电的电压估算百分比；缺少有效采样时显示 `--%`。约 15% 会变为黄色并发出低电量提示。开机、按键、收码、登录、登记和删除各有声音反馈，错误使用较长低音。

## 异常处理

- **配网失败或未授权**。检查 2.4 GHz 网络和 PLM 设备审核状态。设备停用或经办人被移除会使会话失效。DNS 或网络时间不可用时，先恢复网络再按刷新，HTTPS 会校验证书。
- **找不到物料、编号冲突、库存不足或项目权限变化**。界面显示 PLM 返回原因。编号冲突时使用物料二维码定位。图片单独读取；图片错误时仍可正常登记。
- **请求断开或结果未知**。固件在发送前把完整登记、经办人、服务器地址和随机请求编号写入 NVS。回仓库首页、保留空输入并按 **确定**，由原经办人用同一请求编号重试。服务端去重，重启后也不会自动提交。
- **原登记待确认且无法重试**。管理员先在 PLM 核对流水和实际库存。确认可以放弃重试后，串口输入 `clear-pending CONFIRMED-IN-JPLM`。不要在网络超时时用此命令。串口 `status` 显示连接、登录、PSRAM、电池及待确认状态。
- **删除失败**。同一条记录的删除可安全重试。记录被修改、有关联退库或无法回算库存时，刷新历史并按服务端提示处理。

## 本地路由

设备通过办公室 DHCP/DNS 访问 `https://work.makagic.com/JPLM/`。办公室路由命中时屏幕显示「局域网」，外网显示「云端」。缩略图使用现有附件缓存及独立 ETag，缓存读取仍经云端鉴权。应用数据、历史和库存写入实时访问云端。

Wi-Fi 关闭 modem sleep，启动和连接时均请求 ESP32-S3 驱动的最高发射档位 20 dBm。实际功率由驱动按 PHY 速率、射频校准和地区设定决定。同名接入点按信号强度选择，速率由 Wi-Fi 协商。顶部信号条和旁边的数字表示接收信号强度（dBm），大约每 1.5 秒更新，数字越接近零信号越强。重连或切换接入点后会重新检测路由，探测失败显示「路由重查」，约 5 秒后重试。

连上 Wi-Fi 后立即通过 HTTPS 拉取用户列表，并用同一份响应的 PLM 服务器时间校时。旧版 PLM 仍可通过 HTTPS 响应的 `Date` 标头校时，SNTP 在后台继续作为备用。若更换为启用了证书日期校验的 SDK，首次 TLS 连接需要等待 SNTP。频繁操作期间复用 HTTPS 连接，长时间空闲后从按下扫码键或开始输入时准备连接。缩略图独立于查料和库存操作。115200 串口记录 Wi-Fi、时间同步、连接、响应头和正文耗时。

串口 `status` 同时显示最近信号强度、Wi-Fi 断开次数、最近断线原因码和本次启动的复位原因。Wi-Fi 已连接时，串口及无线调试的状态还显示发射上限读回值、休眠状态、当前接入点和信道。若出现重连，可结合 `WiFi disconnected` 和 `Scanner boot` 两类日志区分是网络断开还是主板复位。

## 无线调试

仓库首页按 **上** 开启无线调试。电脑或手机与扫码枪接入同一受信任的局域网，在浏览器打开屏幕上的 `http://扫码枪IP:2323/`，输入屏幕上的 8 位连接码。网页会自动刷新 Wi-Fi 信号、断线原因、本地路由和 PLM 请求耗时。调试开启期间，设备保留最近 8 KB 日志。设备恢复连接且 IP 未变时，网页会自动重连。

从 0.2.8 起，页面记录扫码触发、UART 收码方式、耗时、坏帧和超时，并标记查料来源及本机预览缓存是否命中。PLM 请求和结果用同一个 `#编号`，可查看 HTTP 状态、连接是否复用、连接及收包用时、收包字节数、失败阶段和重试。`bytes=已收/预期` 中的 `-1` 表示服务器未提供长度；缩略图有缓存响应头时会显示 `HIT`、`MISS` 等结果。日志省略原始二维码、设备密钥、登录令牌和请求正文。

调试页按 **返回** 可继续扫码和查料。回到仓库首页按 **上** 打开调试页，再按 **确定** 关闭。调试模式 30 分钟后也会自动关闭，关闭后释放日志缓冲并停止监听。网页只提供诊断日志，通过局域网 HTTP 连接，连接码每次开启重新生成。

## 远程固件升级

1. 首次用 USB 烧录 0.2.7 或更新的仓库应用，并在 PLM 审核启用这台扫码枪。
2. 新版本修改 `include/firmware_version.h` 中的版本号，再用 `pio run -e esp32s3` 编译。上传 `.pio/build/esp32s3/firmware.bin`。
3. 在 PLM 的「设置 → 扫码枪」找到目标设备，打开「固件升级」，选择文件并安排升级。设备联网后每约 15 秒检查一次，空闲且电量允许时通过现有 HTTPS 连接下载。正在录入数量、确认删除或有库存操作待确认时会延后升级。

固件写入备用分区，校验 SHA-256 和 ESP 应用镜像，并确认升级任务仍有效后才切换启动分区。下载中断时继续使用原固件并等待重试。重启后首次成功拉取用户列表会确认新固件，PLM 随后显示已安装。当前分区表含两个 0x640000 字节的应用槽，升级文件须在此大小以内。无线调试和远程升级可独立使用。

默认使用内置的 JPLM CA 根证书、瀚彩初始化序列、SPI mode 3、旋转 2 和背光高有效。若更换服务或屏幕，可按需复制 `include/local_config.example.h` 为 `include/local_config.h`。本机逻辑测试为 `pio test -e native`。

仓库应用使用纯黑底，高饱和绿色用于通用主操作和选中状态，入库用橙、出库用蓝、报废用红。历史记录以彩色区分操作类型，数量统一用白字。主界面顶部显示连接类型、信号强度和电量，完整 IP 在无线调试页。选人名单用放大的 20 像素字形，列表提供方向键选中反馈，扫码时显示扫描线。物料照片沿用 80×80 的服务器数据，在设备端平滑放大到 120×120 并渐进显示，库存与管理员信息在图片右侧。中文和大号数字使用内置抗锯齿字库。字库来源、许可证及生成命令见 [fonts](fonts/README.md)。
